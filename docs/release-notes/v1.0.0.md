# ginn 1.0.0 release notes

Status: draft, 2026-10-16. The tag `v1.0.0` is not cut yet. The release repository is **unsigned**. Read the known limitations before you install.

## Summary

ginn 1.0.0 creates Realms for Arch Linux, Debian, Fedora and Kali Linux on a Void Linux glibc x86_64 host, with rootless Podman. A Realm holds only its image, the Integration Package Set and the packages you ask for. The release covers the Realm lifecycle, package installation through the native package managers and AUR builds, desktop and command export, permission tiers, services mode under runit, rebuild and update, crash-safe operations, and the Control Plane GUI.

The release does not meet every release gate of [GINN-SRS-001 v1.0](../../GINN-SRS-001-v1.0.md) section 9. The sections below list each gate that is not met, with its reason, and the host runs still open. Host gate results are filled in at the end of this file.

## Install

The packages, the repository index, the checksums, the source tarball and the xbps-src template are attached to the GitHub release. The repository is unsigned, so `xbps-install` reads it from a local directory. The steps are in the [README](../../README.md#install). No signing fingerprint exists for 1.0.0. A signed repository follows the maintainer's release key (docs/packaging.md).

## Highlights

### Realm lifecycle (M2 to M4)

- `ginn create`, `start`, `stop`, `status`, `list`, `enter`, `exec` and `delete` for Arch Linux, Debian and Fedora (FR-010, FR-016, FR-019, FR-020, FR-048, FR-049).
- Images are pinned by digest in the trust manifest and checked before use (FR-011, DR-040). A realm gets only the Integration Package Set for its distribution (FR-013).
- Each realm has its own container and Realm Home. Non-Kali realms use `--network host` (FR-026).
- Owned Paths, atomic records, per-realm locks, a journal and an Audit Log (FR-122 to FR-124).

### Host Setup, doctor and integrity (M3)

- `sudo ginn host-setup --user NAME` once, idempotent, with `--undo` (FR-001 to FR-003).
- `ginn doctor` (FR-007) and the host integrity baseline with `ginn integrity --ack` (FR-006).

### Packages, desktop and command export (M5)

- `ginn install` and `ginn remove` through the native package manager, with the Install Manifest (FR-040, FR-041). `ginn install --aur` builds an AUR package in a transient build (FR-043).
- Desktop entries are exported and unexported after each package change, and a watcher syncs the menu (FR-044, FR-045). `ginn export --bin` and `ginn unexport --bin` manage CLI launchers (FR-047).

### Permission tiers, Agent Proxy, D-Bus filter and NVIDIA (M6)

- Basic, Development and Custom tiers, with `ginn tier` and `ginn perms`. A tier change takes effect at the next start (FR-060 to FR-066).
- Agent Proxy: a filtered SSH agent socket for Development realms, with a fixed set of replies (FR-067, NFR-SEC-007).
- Session D-Bus through xdg-dbus-proxy, started on first use (FR-068).
- NVIDIA driver grant through a generated CDI spec (FR-069, ADR-012).

### Services mode (M7, ADR-014, ADR-015)

- `ginn services ARCH on|off` (FR-083) and `ginn autostart` (FR-084). A services-on realm runs under a runit service (FR-080, FR-081).
- Five start crashes within 60 s leave the realm `failed` (FR-081 AC-3, ADR-014).
- The exec relay routes `ginn exec` and install into a services-on realm through its supervisor (ADR-014).
- ADR-015 installs the init set into a services-on realm at create, through a provisioning stage that builds a derived image with the distribution's own package manager. The init set is systemd and D-Bus: `systemd`, `systemd-sysv` and `dbus` on Debian and Kali, and `systemd` and `dbus-broker` on Fedora. Arch's pinned image already ships systemd, so its set is empty. The pinned Debian, Fedora and Kali images have no `/sbin/init` (F1), so this stage is what lets a services-on realm start on them (FR-080). The stage is merged into `void` for 1.0.0. Its host gate (T7.27) has not run yet; see the gate table.

### Rebuild, update, failure handling (M8)

- `ginn rebuild` builds a new root beside the old one from the pinned image, replays the Install Manifest, and swaps the roots in one record write. A package the upstream no longer offers is reported with GINN-W-REPLAY-MISSING and left out (FR-021, FR-022).
- `ginn update` (FR-023) and `ginn update --check` (FR-024).
- Network retries, a disk space check before a create or rebuild (FR-120, FR-121), and `ginn create --resume` for an interrupted create (FR-122).
- Crash safety: the mutating operations are tested with a simulated kill at each durable-effect point (FR-122, NFR-030, NFR-031). Host SIGKILL runs are open (see below).

### Control Plane GUI (M9)

- `ginn-gui`, a GTK4 and libadwaita window: realm dashboard, create wizard, realm detail with confirmations, permissions editor, host health view and progress with cancel (FR-100 to FR-107).
- Every change calls the `ginn` CLI, so the GUI and the CLI give the same results (FR-106).
- The GUI does not install applications (OOS-5).

### Kali (M10)

- Kali realms run on `--network pasta` with `NET_RAW`. Raw sockets work inside the realm's own network namespace only (FR-026, FR-027).
- `ginn create kali --everything` estimates the size, asks for confirmation (or `--yes`), and then installs the full set (FR-014).
- The Kali image is pinned like the others. Its help text states the out-of-scope items (OOS-9, R-002).

### Verification and release tooling (M10)

- `tools/measure/` scripts for NFR-001 to NFR-005, NFR-007 and NFR-011, `tools/host-diff.sh`, `tools/trace-no-xbps.sh`, and the verification report (`docs/verification-report.md`).
- `tools/release.sh` builds the unsigned repository, and signs it when a release key is given. It is run only in the CI build container or by the maintainer.

## Known limitations: requirements and measurements

- **Services on Debian, Fedora and Kali.** The ADR-015 provisioning stage is merged, and its unit tests pass. Its host gate has not run, so the init set install, systemd as PID 1 and zero failed units on these three distributions are not yet proven on a host. In the ADR-015 S-11 spike (three boots, VmRSS median), Debian read 32.34 MiB, Fedora 62.25 MiB, Kali 31.01 MiB and Arch 33.98 MiB. Fedora is over the 40 MiB NFR-003 budget, which is open (ADR-015 Decision 11). Arch has one run at 12.21 MiB that is open (ADR-015 open question 8).
- **Memory (NFR-003, NFR-021).** The verification draft of 2026-10-14 records FAIL: the arch realm's VmRSS median was 87.11 MiB against 40 MiB, and five arch realms totalled 437.34 MiB against 200 MiB (the state before the F6 fix). A later run on 2026-10-15 (`spikes/results/T7.16-relay-gates.md`, section 5) recorded a VmRSS median of 33.71 MiB and 168.97 MiB for five realms. That run is not yet in the draft verification report. The per-distribution NFR-003 run is ADR-015 host gate item 4.
- **NFR-004 under load.** The p95 launch latency is 129.1 ms at load 5 to 8, which meets the 300 ms target. At load 24 it is 453.3 ms, which fails. The idle re-measure is open.
- **NFR-005.** The start-to-running p95 is 0.107 s over 20 cycles on debian. The 50-cycle run on each distribution is not done.
- **NFR-007.** One create on debian took 4.758 s. The 3-run, 100 Mbps run on each distribution is not done.
- **NFR-006, NFR-008, NFR-009, NFR-010.** Not run. These need a GPU benchmark realm, a disk accounting run, a 20-run export timing, and the GUI state probe.
- **NFR-011.** The synthetic 5,000-file run passes (p95 0.084 s). The host scope (about 44,600 entries) is not run.
- **FR-085** (a Docker daemon in a services-on realm) is deferred (CL-2). It is not built.
- **Key-leak tests (gate 6).** FR-062 AC-1, AC-3 and AC-4, and FR-067 AC-1 and AC-2, have no host run (T6.8, section 4). FR-067 AC-1 was skipped in the T6.8 host gate, because the image has no `ssh-add`.
- **Two-user tests** (FR-025, NFR-SEC-008, NFR-SEC-010) need a second host user. Not run.
- **Real logout** (CL-5, FR-084, T7.8): the session socket re-attach after a logout is not run.
- **Manual walkthroughs** (NFR-050, NFR-051: first realm from the GUI in five actions; keyboard and screen reader) are the user's, and are not run.
- **Kali on a host.** No Kali realm was created on a host through ginn (FR-026). The pasta and `NET_RAW` argv is proven by spike S-09 (FR-027 AC-1 and AC-2).
- **Unsigned repository.** Packages and the index are not signed. See the README install section.

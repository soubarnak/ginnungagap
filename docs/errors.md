# Error catalogue

Generated by `tools/gen_errors_doc.py` from `src/ginn/errors.py`. Do not edit by hand.

Placeholders in braces, such as `{name}`, are filled in at run time.

Exit status 125 is not used by any code below. `ginn exec` returns the inner command's exit status, so ginn-side failures of `exec` and `enter` exit 125 instead (IR-011, FR-049).
Only a `GINN-E-` line on stderr, or a JSON error object, marks a ginn failure of `exec` or `enter`. A 125 that podman or the command returns on its own is passed through unchanged, so the exit status alone does not tell the two apart. The exceptions are the argparse refusals (exit 2) and Ctrl-C (130).

## Exit statuses

| Exit | Meaning |
|---|---|
| 0 | success. `GINN-W-*` warnings also keep 0: they are notices, not exceptions. |
| 1 | operational failure: GINN-E-PKG-MANAGER, GINN-E-DOCTOR-FAILED, GINN-E-ATTACH-FAILED, GINN-E-REALM-USER, GINN-E-AGENT-FILTER, GINN-E-DBUS-PROXY, GINN-E-NVIDIA-STALE, GINN-E-NVIDIA-CDI, GINN-E-HOST-DEVICE, GINN-E-SECCOMP-SOURCE, GINN-E-SUPERVISOR-DOWN, GINN-E-SERVICE-TIMEOUT, GINN-E-SERVICE-CONTROL, GINN-E-SERVICE-MISSING, GINN-E-NO-INIT, GINN-E-RELAY-UNAVAILABLE, GINN-E-RELAY-REJECTED, GINN-E-RELAY-TIMEOUT, GINN-E-RELAY-LOST |
| 2 | input validation: usage, names, options, paths |
| 3 | not found: GINN-E-NO-SUCH-REALM |
| 4 | conflict with existing state: name taken, undo refused, unacknowledged host change, interrupted operation not yet recovered, a realm in a state its verb does not allow (GINN-E-REALM-STATE), a removal that would take other packages (GINN-E-PKG-DEPENDENTS), a realm whose shares and toggles need a Custom tier (GINN-E-TIER-NOT-CUSTOM) |
| 65 | data error (EX_DATAERR): image or package signature not verified |
| 69 | network failure |
| 70 | internal error (EX_SOFTWARE) |
| 73 | not enough disk space |
| 75 | realm, subordinate ID file or Host Setup busy, the exec relay at its worker limit (GINN-E-RELAY-BUSY), or a service still running at undo (EX_TEMPFAIL) |
| 77 | Host Setup must run as root, has not run for this user, or refuses an unsafe path it cannot repair (EX_NOPERM) |
| 125 | ginn-side failure of `ginn exec` and `ginn enter`, marked by a GINN-E line or JSON error object on stderr; a 125 from podman or from the command is passed through unchanged |
| 130 | interrupted by the user |

Run: 2026-10-12, Void glibc x86_64, kernel 7.2.9_1, rootless podman 5.8.8, crun 1.30.1. Script: `spikes/s04_s08_logout.sh` (`s08-*` subcommands), helpers `spikes/s04_s08_sockserver.py`, `spikes/s04_s08_probe.sh`, `spikes/s04_s08_rebind.py`. Same throwaway user and private sshd as S-04 (see `spikes/results/S-04.md`, which holds the root command list and cleanup proof).

## Verdict

S-08: invalid: no elogind session. Not run.

S-08 depends on S-04's login setup. An ssh login as `ginn-spike` did not register with elogind, so `/run/user/<uid>/s08.sock` could not be created in a login session, and the logout that tears down the runtime dir could not be tested. Nothing about CL-5 was measured.

CL-5 stays open. It is not resolved to "restart required", because the unprivileged rebind was never attempted.

## What was prepared, not executed

- `s08-start`: gen1 socket server at `/run/user/<uid>/s08.sock`, container `s08c` (flags as S-04 variant A, own storage under `/run/ginn/<uid>/s08`) bind-mounting it at `/run/s08.sock`, plus a baseline probe.
- `s08-server2`: gen2 server at the same path after a new login.
- `s08-probe`: `stat` of `/run/s08.sock` inside the container, then a connection and the reply (`nc -U`, to be checked in alpine's busybox).
- `s08-rebind`: `spikes/s04_s08_rebind.py` run first under `podman unshare`, then in the session's own namespaces. It opens the host socket with `open_tree(OPEN_TREE_CLONE)` (syscall 428), enters the container's user and mount namespaces with `setns`, and calls `move_mount` (429) onto `/run/s08.sock`. No root.

None of this ran. The `nc -U` check, the `setns` ownership rule and the `podman unshare` case are all untested assumptions.

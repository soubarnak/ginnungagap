# S-06: GPU on Wayland and X11 in a rootless realm; NVIDIA via self-generated CDI

Requirements FR-046 (exported app renders on Wayland and X11, GL renderer not software), FR-061 (Basic tier grant), FR-069 (NVIDIA proprietary driver through host libraries and device nodes, `nvidia-smi` shows the host driver). Risk R-005 (stale driver against bind-mounted libraries). Interfaces IR-025, IR-026.

**Verdicts**

```
FR-046 Wayland: PASS
FR-046 X11: PASS
FR-069: PASS
```

The roadmap pass criterion is "non-software renderer; `nvidia-smi` shows host driver". Both hold on the AMD GPU (Wayland and X11) and on the NVIDIA GPU (`nvidia-smi`, GLX offload, EGL surfaceless, Vulkan).

## 1. Environment

- Host: Void Linux, glibc 2.41, kernel 7.2.9_1, Wayland session (`WAYLAND_DISPLAY=wayland-1`, `DISPLAY=:0` served by Xwayland, `XDG_RUNTIME_DIR=/run/user/1000`). `XAUTHORITY` unset on the host.
- GPUs: AMD Radeon 660M (`card0`, `renderD128`, driver `amdgpu`, PCI 05:00.0). NVIDIA GeForce RTX 2050 (`card1`, `renderD129`, driver `nvidia-drm`, PCI 01:00.0). The task brief said 680M; the host reports 660M.
- NVIDIA kernel driver 595.104.02 (`/proc/driver/nvidia/version`). Device nodes: `/dev/nvidia0`, `/dev/nvidiactl`, `/dev/nvidia-modeset`, `/dev/nvidia-uvm`, `/dev/nvidia-uvm-tools`, `/dev/nvidia-caps/nvidia-cap1` (mode 0400, root), `/dev/nvidia-caps/nvidia-cap2` (mode 0444).
- Host Mesa 26.2.4 (`/usr/sbin/glxinfo`). Host `nvidia-smi` at `/usr/sbin/nvidia-smi`. No host `eglinfo` or `vulkaninfo`.
- podman 5.8.8, rootless, OCI runtime runc. crun is not installed.
- Realm image `localhost/ginn-s06:debian-stable` from `docker.io/library/debian:stable` (Debian trixie): Mesa 25.0.7-2+deb13u1, glibc 2.41-12+deb13u4, glmark2-x11 2023.01. No NVIDIA packages.
- Dedicated storage: `--root ~/.local/share/ginn-spike-s06/podman --runroot $XDG_RUNTIME_DIR/ginn-spike-s06`. Removed by teardown (verified: no containers, no mounts, no directories left).

## 2. Basic-tier display, audio and GPU grant (FR-061)

Exact argv. The global flags come before `run`. `--cdi-spec-dir` is a global podman flag; `podman run --help` does not list it.

```sh
podman --root ~/.local/share/ginn-spike-s06/podman \
  --runroot $XDG_RUNTIME_DIR/ginn-spike-s06 \
  run -d --name s06-basic \
  --userns keep-id --network host \
  --device /dev/dri --group-add keep-groups \
  --tmpfs /run/user/1000:mode=0700,U \
  -v $XDG_RUNTIME_DIR/wayland-1:/run/user/1000/wayland-1 \
  -v /tmp/.X11-unix:/tmp/.X11-unix \
  -v /usr/share/fonts:/usr/share/fonts:ro \
  -v /etc/localtime:/etc/localtime:ro \
  -e WAYLAND_DISPLAY -e DISPLAY -e XDG_RUNTIME_DIR=/run/user/1000 \
  -v $XDG_RUNTIME_DIR/pipewire-0:/run/user/1000/pipewire-0 \
  -v $XDG_RUNTIME_DIR/pulse/native:/run/user/1000/pulse/native \
  localhost/ginn-s06:debian-stable sleep infinity
```

Differences from the brief, each observed:

- `--init` is refused: `lookup init binary: exec: "catatonit": executable file not found`. Catatonit is absent on the host and in the image (same as S-02). The grant runs without `--init`. FR-082 still needs catatonit from packaging or Host Setup.
- `--tmpfs ...,uid=1000,gid=1000,mode=0700` is refused: `unknown mount option "uid=1000"`. `U` is accepted and yields owner 1000:1000, mode 0700 (checked with `stat`). Plain `mode=0700` gives owner 0:0.
- `--group-add keep-groups` is accepted by runc but has no effect. The realm user keeps only its own group (`groups=1000`). Basic GPU access works without it: `card0` has a user ACL (`crw-rw----+`) and the render nodes are mode 0666. Inside the realm the device nodes show as `nobody:nogroup`, because host root is not mapped under keep-id. Re-test with crun before deciding (crun not installed here).
- `XAUTHORITY` is unset on this host, so no auth file is mounted. The mount is in the script for hosts that set it.
- Audio: the sockets are bound and visible (`srwxrwxrwx` for both). The connection test is skipped, because `pulseaudio-utils` is not in the image list and the brief says to skip. Audio is therefore unverified (see open items).

Realm `/run/user/1000` after the grant: `wayland-1`, `pipewire-0` and `pulse/` (the `pulse` parent dir is root-owned 0755, created by runc; the native socket is connectable by mode).

Basic grant device nodes (what `--device /dev/dri` exposes): `card0`, `card1`, `renderD128`, `renderD129`. `card1` and `renderD129` belong to the NVIDIA DRM driver, so the Basic grant exposes the NVIDIA DRM nodes too. Mesa did not use them (see section 3).

## 4. NVIDIA via self-generated CDI (FR-069)

Approach: `spikes/s06/nvidia-cdi.py` (stdlib only, run as `python3 -I`). It reads the host driver files and writes `$DATA/cdi/nvidia.json` (`cdiVersion` 0.6.0, kind `nvidia.com/gpu`, device `all`) plus `$DATA/ld/ginn-nvidia.conf` (the ld.so.conf drop-in, `/usr/lib/ginn-nvidia`). Outputs for this run:

- 7 device nodes in `containerEdits.deviceNodes`: `/dev/nvidia-caps/nvidia-cap1`, `/dev/nvidia-caps/nvidia-cap2`, `/dev/nvidia-modeset`, `/dev/nvidia-uvm`, `/dev/nvidia-uvm-tools`, `/dev/nvidia0`, `/dev/nvidiactl`. Each has major, minor and `rwm`.
- 70 read-only bind mounts (`ro,nosuid,nodev,bind`):
  - 62 libraries. Each matched glob name (real file or symlink name) is mounted to `/usr/lib/ginn-nvidia/<name>`, with the realpath as hostPath, so the SONAME names exist without a symlink step.
  - 6 vendor JSON files kept at their host paths: `/usr/share/glvnd/egl_vendor.d/10_nvidia.json`, `/usr/share/vulkan/icd.d/nvidia_icd.json`, `/usr/share/vulkan/implicit_layer.d/nvidia_layers.json`, and three `/usr/share/egl/egl_external_platform.d/*nvidia*` files.
  - `nvidia-smi` (`/usr/sbin/nvidia-smi` on the host) at `/usr/bin/nvidia-smi`.
  - The ld drop-in at `/etc/ld.so.conf.d/ginn-nvidia.conf`.
- No hooks, no CDI `env`.
- R-005 check, emitted by the generator: `proc_driver_version` 595.104.02; `lib_versions` [595.104.02]; `stale_libs` []. Every versioned library matches the kernel driver.

Podman accepted the spec at `--cdi-spec-dir` with `--device nvidia.com/gpu=all`. Device nodes and mounts worked rootless.

### ldconfig question

Three ways the realm loader can find the bind-mounted libraries:

| Variant | Command | Result |
|---|---|---|
| (c) drop-in only, no ldconfig | `nvidia-smi` | rc 12: `NVIDIA-SMI couldn't find libnvidia-ml.so library in your system.` The loader reads only `/etc/ld.so.cache`, so the drop-in alone does nothing. |
| (a) `LD_LIBRARY_PATH` | `env LD_LIBRARY_PATH=/usr/lib/ginn-nvidia nvidia-smi` (keep-id user, no ldconfig) | rc 0, works |
| (b) ldconfig as container root | `podman exec --user 0:0 s06-nv ldconfig`, then `nvidia-smi` as the keep-id user | ldconfig rc 0, `nvidia-smi` rc 0, works |

`ldconfig -N` does not write the cache, so it cannot answer this and was not used. ldconfig as the keep-id user cannot write `/etc/ld.so.cache`. Container root maps to subuid 100000, so `--user 0:0` can write it in the container's upper layer. That cache is lost when the container is recreated.

Recommendation for M6: use variant (a), and set `LD_LIBRARY_PATH=/usr/lib/ginn-nvidia` through CDI `containerEdits.env`. That needs no root step, and the drop-in can then be dropped from the spec. This form was tested with `podman exec -e`, not with the CDI `env` field, so M6 must test the CDI env field first. Keep variant (b) as the fallback if the libraries must resolve for processes that do not inherit the environment.

### R-005: stale driver

Host `/proc/driver/nvidia/version` reports 595.104.02. Every library version in the spec matches it, so there was no mismatch this run.

Two points for M6, from the design of the spec. These are inferences; neither was tested:

- The mounts name versioned host files (for example `libnvidia-ml.so.595.104.02`). A driver upgrade removes those names, so the next container start fails at the mount step until the spec is regenerated. M6 must regenerate the spec when `/proc/driver/nvidia/version` changes, and check `stale_libs` (this matches T6.6: ldconfig once per driver version).
- The NVML error for a real mismatch, `Failed to initialize NVML: Driver/library version mismatch`, was not reproduced. No second driver version exists on the host to create one.

## 6. Open items

- Audio connection not tested: no pactl in the image. Add `pulseaudio-utils` in a follow-up and run `pactl info` against the bound `pulse/native` and `pipewire-0`.
- Bare `eglinfo` picks llvmpipe through the GBM platform. Any GPU check must name the platform (`-p wayland`, `-p x11`). Needs root-cause before M6 relies on GBM clients.
- NVIDIA EGL on the Wayland platform fails `eglInitialize`. Surfaceless EGL works. Not root-caused; FR-046 passes on AMD, so this is not a gate for it.
- `--group-add keep-groups` needs a crun test before it is relied on.
- catatonit is still missing (FR-082).
- Realm `HOME` is `/` (keep-id sets no home). Mesa then logs `Failed to create //.cache for shader cache (Permission denied)`. M6 must set `HOME` and `XDG_CACHE_HOME`.
- `nvidia-cap1` is unreadable from the realm. Decide whether the generator should skip nodes the user cannot open.
- R-005 mismatch signature not reproduced.

## 7. Recommendations for ADR-008

1. Basic grant: the argv in section 2, with `--tmpfs ...:mode=0700,U` (not `uid=`), and no `--init` until catatonit is packaged (FR-082).
2. Always name the GL platform in GPU checks (`eglinfo -p wayland`, `glxinfo` with `DISPLAY`). A bare `eglinfo` reports llvmpipe through GBM.
3. NVIDIA: generate the CDI spec with `spikes/s06/nvidia-cdi.py` logic (libraries under `/usr/lib/ginn-nvidia`, versioned names, realpath sources, vendor JSON at host paths, `nvidia-smi` at `/usr/bin`). Set `LD_LIBRARY_PATH=/usr/lib/ginn-nvidia` through CDI `containerEdits.env`, and test that form. Keep ldconfig as `--user 0:0` as the fallback.
4. Regenerate the spec whenever the kernel driver version changes (R-005). Refuse to start when `stale_libs` is not empty.
5. Do not treat `DRI_PRIME=1` as the NVIDIA path. Use `__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia` for NVIDIA GL.
6. Set `HOME` and `XDG_CACHE_HOME` in the realm environment.

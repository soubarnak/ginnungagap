# S-04: runtime root across logout (CL-1, ADR-004)

Run: 2026-10-12, Void glibc x86_64, kernel 7.2.9_1, rootless podman 5.8.8, crun 1.30.1, elogind 1021 (pid), uid 1001 for the throwaway user `ginn-spike`. Script: `spikes/s04_s08_logout.sh` (subcommands in its header). Raw logs, including `root-commands.log`, are in the session scratchpad, outside the repository. The control socket for ssh lived in `~/.cache/ginn-s04-ctl` (removed).

## Verdict

S-04: invalid: no elogind session.

The precondition failed. An ssh login as `ginn-spike` did not register with elogind, so `/run/user/1001` was never created. The logout test measured nothing about variant A or variant B. No container was started, so no `podman` storage was created. Per the brief, the run stopped and was cleaned up.

## Precondition evidence

- PAM stack: `/etc/pam.d/sshd` includes `system-remote-login`, which includes `system-login`. `system-login` has `-session optional pam_elogind.so`. `/usr/lib/security/pam_elogind.so` is present. `pam_turnstile` and `pam_dumb_runtime_dir` are not in use.
- The sshd session did open a PAM session. `/var/log/socklog/secure/current` has `pam_unix(sshd:session): session opened for user ginn-spike(uid=1001)`. Inside the login, `/proc/self/loginuid` is 1001 and `/proc/self/sessionid` is 4.
- Inside the login: `XDG_SESSION_ID` unset, `XDG_RUNTIME_DIR` unset, `/run/user/1001` absent. `/proc/self/cgroup` showed `1:name=elogind:/` and `0::/2`.
- `loginctl list-sessions` inside the login listed only `2 1000 soubarna seat0 tty7`. The ginn-spike session was not listed.
- Two login styles were tried. One was a ControlMaster connection without a pty. The other was `ssh -tt` (`/dev/pts/2`) on a separate connection. Both failed the same way.
- pam_elogind wrote no error for the sshd sessions. The only pam_elogind error on record is from 2026-10-10 (greetd: system bus unreachable).
- `/run/systemd/system` does not exist. This is observed only. It was not verified as the cause.
- `KillUserProcesses`: `/etc/elogind/logind.conf` line 16 is `#KillUserProcesses=no`, commented, so the default (no) applies.
- Finding for the procedure: sshd opens and closes a PAM session per channel command (`Starting session: command` and `Close session` for each `ssh` command in `sshd.log`). One ControlMaster connection is therefore not one PAM session. Each `rx` call is its own session.

Evidence copies: `<scratch>/evidence/precheck-evidence.txt`.

## Root commands, in order

Every state-changing root command went through the wrapper, which logged it before running it. `sudo -n` read-only checks are listed after this list.

1. `useradd -m ginn-spike` (13:15:15). Created uid 1001, gid 1002, home `/home/ginn-spike`, shell `/bin/bash`. useradd auto-allocated `ginn-spike:265536:65536` in both `/etc/subuid` and `/etc/subgid`.
2. `sed -i /^ginn-spike:/d /etc/subuid /etc/subgid` (13:16:08). Removed the auto-allocated lines. The brief asked for hand-added lines.
3. `tee -a /etc/subuid` with `ginn-spike:300000:65536`.
4. `tee -a /etc/subgid` with `ginn-spike:300000:65536`. The range does not overlap `100000`, `200000` or `1000000`.
5. `install -d -m 0700 -o ginn-spike -g ginn-spike /home/ginn-spike/.ssh`.
6. `install -m 0600 -o ginn-spike -g ginn-spike <scratch>/id_ed25519.pub /home/ginn-spike/.ssh/authorized_keys`.
7. `mkdir -m 0755 /run/sshd`. The privsep directory was absent. Removed in step 19.
8. `/usr/sbin/sshd -f <scratch>/sshd_config -E <scratch>/sshd.log -o ListenAddress=127.0.0.1 -o Port=2222 -o PasswordAuthentication=no -o UsePAM=yes`. Private sshd, pid 17744, own host key, PidFile in scratch.
9. `mkdir -m 0755 /run/ginn` (13:16:12).
10. `mkdir -m 0700 /run/ginn/1001`.
11. `chown ginn-spike:ginn-spike /run/ginn/1001`.
12. `chmod 0700 /run/ginn/1001`.
13. `kill 17744` (13:17:33). The pid was checked first: `/proc/17744/cmdline` is the private sshd with our config path.
14. `rm -rf /run/ginn` (13:17:35). Contained only `1001`.
15. `userdel -r ginn-spike` (13:17:35). Printed only `mail spool /var/mail/ginn-spike not found`.
16. `sed -i /^ginn-spike:/d /etc/subuid /etc/subgid`. Removed the remaining lines, if any.
17. `install -m 0644 -o root -g root <scratch>/orig/subuid /etc/subuid`. Restored the saved original. The line set matched already, but useradd had re-sorted the file, so the order differed. The saved copy was restored byte for byte.
18. `install -m 0644 -o root -g root <scratch>/orig/subgid /etc/subgid`. Same reason as step 17.
19. `rmdir /run/sshd`. Removed the empty privsep directory we created.

Read-only root checks, run as `sudo -n` directly and not through the wrapper. None changed state:
- `sudo -n true` (sudo check).
- `sudo -n loginctl list-sessions`, four times, at each login and logout.
- `sudo -n tail`, `grep` and `cat` on `<scratch>/sshd.log`, `/home/ginn-spike/.ssh` (ls, authorized_keys), and `/var/log/socklog/{secure,errors,daemon}`.

## Cleanup proof

- Private sshd stopped. `/dev/tcp/127.0.0.1/2222` refused after the kill.
- No `ginn-spike` processes remained (`pgrep -u ginn-spike` empty before `userdel`).
- After `root-teardown`:
  - `getent passwd ginn-spike`: absent.
  - `/home/ginn-spike`, `/run/ginn`, `/run/sshd`, `/run/user/1001`: absent.
  - `diff` of `/etc/subuid` and `/etc/subgid` against the saved originals: identical.
- ssh control directory `~/.cache/ginn-s04-ctl` removed.
- Not removed, and not inspected: host logs written during the run. These include `/var/log/socklog/secure` (sudo and sshd-session entries), and possibly `wtmp`, `btmp` and `lastlog` entries for uid 1001. They are host logs, outside the cleanup list.

## What is needed to rerun

An ssh login for a non-root user must register an elogind session, so that `loginctl` lists it and `/run/user/<uid>` is created. That is host configuration (elogind or PAM), outside this spike's authorization. The unverified lead is `/run/systemd/system` being absent. Rerun with `spikes/s04_s08_logout.sh` once that holds.

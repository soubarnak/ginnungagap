# S-01: systemd as PID 1 in rootless podman under a delegated cgroup (R-001)

Run: 2026-10-12, host Void Linux glibc x86_64, kernel 7.2.9_1, runit, elogind.
Script: `spikes/s01_systemd_rootless.sh` (runc leg). crun leg: `spikes/s01c_crun.sh`. Raw logs stayed outside the repo (per-variant `podman top`, `journalctl`, `root-steps.log`).

## Verdict

**S-01: PARTIAL**

The roadmap pass criterion (`systemctl is-system-running` is running or degraded, zero failed default units) holds with runc under a root-created, user-owned, delegated cgroup subtree (variants a and c). These are the earlier runs, which did not pin XDG_RUNTIME_DIR (see Disclosures). The crun leg did not boot. Its one required step, placing the launcher shell in a leaf under `/sys/fs/cgroup/ginn/1000`, needs a root write to `cgroup.procs`. The crun brief's root allowance does not cover that write, so it was not run. Without it, crun and a pinned runc both fail with EACCES (see S-01 crun leg). Variant b cannot run as specified: podman 5.8.8 rejects `--cgroups=split` together with `--cgroup-parent`. The roadmap gate ("stop if S-01 fails on both runtimes") is not triggered, because runc passed on the earlier runs. FR-080 AC-1, FR-080 AC-2 and FR-016 AC-2 are demonstrated on runc (unpinned). NFR-003 is not decided here (see RSS).

## Recommended flag set

```
podman run -d --name <realm> --systemd=always --cgroupns private \
  --cgroup-parent /ginn/<uid>/<realm> --userns keep-id --user 0:0 \
  --network host --stop-signal SIGRTMIN+3 <image> /sbin/init
```

- Use the default cgroups mode. Do not add `--cgroups=split` together with `--cgroup-parent`.
- Run `podman run` and `podman start` from a process that Host Setup placed in a leaf under `/ginn/<uid>` (see the root steps). `podman start` from the session cgroup fails with EACCES. Placement of exec'd processes is unverified.
- The runc default was used. Use crun only after its own run is recorded.
- `--userns keep-id --user 0:0` was not varied; it worked as given.
- The roadmap's services-on set includes `--stop-timeout 30` at create time. This spike did not test that flag. It used `podman stop -t 30` instead. The roadmap set also lacks `--userns keep-id --network host`, which this spike used. Verify both in the ADR-003 author's run before recording the final set.

## Root steps Host Setup (FR-001) must perform

All as root. Here `<uid>` is the user, `<gid>` the user's primary group, and `<leaf>` the leaf that the runit supervisor lives in.

1. Record the original `/sys/fs/cgroup/cgroup.subtree_control` for undo.
2. `echo +cpu`, `+memory`, `+pids`, `+io`, `+cpuset` into `/sys/fs/cgroup/cgroup.subtree_control`. On this host only `+pids` was new.
3. `mkdir /sys/fs/cgroup/ginn`, then the same five `+ctrl` writes into `/sys/fs/cgroup/ginn/cgroup.subtree_control`.
4. `mkdir /sys/fs/cgroup/ginn/<uid> /sys/fs/cgroup/ginn/<uid>/<leaf>`, then the same five `+ctrl` writes into `/sys/fs/cgroup/ginn/<uid>/cgroup.subtree_control`.
5. Place the supervisor process in the leaf: `echo <pid> > /sys/fs/cgroup/ginn/<uid>/<leaf>/cgroup.procs`. The leaf must be a child because `ginn/<uid>` has controllers enabled, so it cannot hold processes itself (no-internal-process rule).
6. `chown <uid>:<gid>` on `/sys/fs/cgroup/ginn/<uid>`, `.../cgroup.procs`, `.../cgroup.threads` and `.../cgroup.subtree_control`. Nothing else under the subtree is chowned, so limit files such as `memory.max` stay root-owned. Chowning the whole tree would let the user raise its own limits.

Undo, in order: remove containers, remove leaves deepest first, `rmdir /sys/fs/cgroup/ginn/<uid>`, `rmdir /sys/fs/cgroup/ginn`, then `echo -pids` into root `cgroup.subtree_control` (the spike restored the recorded original, `cpuset cpu io memory`). Note: if Host Setup keeps `+pids` at root, the ADR should say so.

The spike wrote all of these through `sudo "$0" --root-setup`. Every write and its result is in `root-steps.log`. No write failed.

### Why root is needed (user-only probe)

```
$ mkdir /sys/fs/cgroup/ginn/1000/s01crun-probe            # user mkdir: OK
$ ( echo $BASHPID > /sys/fs/cgroup/ginn/1000/s01crun-probe/cgroup.procs )
/bin/bash: line 1: echo: write error: Permission denied
```

The root cgroup's `cgroup.procs` is `-rw-r--r-- root root`. The probe moves a process out of `/2`, whose common ancestor with `ginn/1000` is the root cgroup. The user cannot write there. Teardown removed the probe leaf.

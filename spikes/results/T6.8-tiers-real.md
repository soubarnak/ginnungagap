# T6.8: M6 tiers host gate on a Void host

Run: 2026-10-13, kernel 7.2.9_1 (Void, glibc). Rootless podman 5.8.8 and crun 1.30.1, the versions recorded in `spikes/results/T4.9b-realm-user.md`; they were not queried again, because the rules forbid a bare `podman` call. The host has `/dev/kvm`, `/dev/fuse`, `/dev/net/tun`, `/dev/dri`, `/usr/share/containers/seccomp.json`, `ssh-agent`, `xdg-dbus-proxy` and `gpgconf`. The host also has an NVIDIA driver; see section 4.

Command: `GINN_INTEGRATION=1 GINN_T49_RESULTS=<file> pytest -v -rs tests/integration/test_tiers_real.py`, after `make -C native` built `native/build/ginn-agent-filter`.

## 1. Two runs, and what changed between them

- Run 1 (`t68-run1`): 8 passed, 1 skipped. The skipped test was `test_fr067_...`. The filter socket directory was the host session directory under pytest's base path, which is longer than the 108-byte limit of a unix socket path, so the test skipped with that reason. No product check ran in that test.
- Change between the runs: the test now starts the filter in a short private directory under `/tmp` (mode 0700, removed afterwards). Its assertions are unchanged, and the `ssh-add` probe now runs before the realm stops, which it did not in run 1.
- Run 2 (`t68-run2`, the final run, on the code in the working tree): 9 passed. Inside the FR-067 test, one item is recorded as SKIP (section 3). Pytest counts that test as passed, because the skip is recorded in the results file rather than raised.

## 2. Setup, and isolation

- Realms `tbasic` (Basic), `tcustom` (Custom) and `tdev` (Development), created by the product create with `CreateHooks(integrate=False)`. Gate 3 is not approved: no refresh, no package step, and no package manager runs in any realm.
- Image: `debian` by the digest pinned in `src/ginn/trust/data/trust.toml` (the same digest as T4.11).
- The host home is the throwaway `host.host_home` of `tests/integration/conftest.py`. The test writes its own `Downloads`, `Documents`, `Music` and `.bashrc` there. The user's real files are never read or written.
- Every probe reads the user's real mount roots (`/media`, `/mnt`, `/run/media/<user>`) as absent, as in `test_lifecycle_real.py`.
- The session runtime directory is an empty directory of the test, never `/run/user/<uid>`.
- NVIDIA: the gate passes a probe that reports no driver. The host does have a driver, but the CDI device path on crun is pending T6.6, so no CDI device was made in any realm.
- Teardown: the conftest stopped the store's pause process (`alive_after_kill: false`), and the realms were stopped by the module fixture.

## 4. What this run does not prove

- FR-062 AC-3 (nested `podman run --rm <image> true`): it needs an image pull inside the realm, which is outside the no-package-install rule of this gate. Its unit-level parts (the argv, the seccomp profile, the realm config files) are tested.
- FR-062 AC-1 (ssh key round trip): needs a key and a server.
- FR-062 AC-4: only the open of `/dev/kvm` ran. The KVM ioctls and a VM are not run.
- FR-067 AC-1 (`ssh-add -D` refused) and AC-2 (`gpg --export-secret-keys` refused): not run. The image has no ssh client, and the gpg extra socket is not resolved in this gate.
- FR-068 (session bus proxy): not in this gate. It is unit-tested only.
- FR-069 (NVIDIA): not run. The probe reported no driver, so no CDI device was made. The CDI path on crun, and the `LD_LIBRARY_PATH` of the CDI env field, stay open under T6.6.
- FR-061: the display, audio, GPU and font grants were not run in this gate (only the Downloads and mount-root folders were exercised, in the Basic realm).
- FR-066 AC-1 (Basic to Development, then `~/Projects` after restart): open until T8.3. The create-time options need a new container (ADR-006 amendment of 2026-10-13); the gate covers only attach-only changes.
- The user's real mount roots were hidden by the probe, so the drive case of FR-065 is not run here.

## 5. Notes for the next reader

- The FR-064 and FR-066 checks depend on the probe that hides the real mount roots, and on the user's `~/Projects` being absent in the test home at the time of the Development start.

### 6.1 Change versus run 2

- Kernel 7.2.9_1 to 7.2.10_1. Every item of section 3 keeps its verdict.
- Socket layout (CL-14): the filter's host socket now lives under ginn's runtime root. FR-067-socket-and-stop still passes. It checks the socket inside the realm and the agent record, and it does not assert the host-side path, so this run does not prove the new host layout on its own.
- Custom toggles (display, audio, gpu, fonts_timezone): no tiers item exercises them, as in run 2. Section 4 still applies to them.
- `--cdi-spec-dir` on every podman call: the gate's own adapter did not pass it, which broke the lifecycle gate (6.3). The tiers gate injects the no-driver probe, so it makes no CDI device, and its verdicts did not change.

### 6.2 Harness change

`tests/integration/conftest.py`, `_build_host`: the gate's `PodmanCli` now gets `cdi_spec_dir=paths.cdi`, as the product adapter does in `_context.podman`. This is a harness-only change. No product code changed.

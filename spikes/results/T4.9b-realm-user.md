# T4.9b: the realm user is podman's keep-id passwd entry

Run: 2026-10-13, Void glibc x86_64, kernel 7.2.9_1, podman 5.8.8 rootless, crun 1.30.1. Image: `docker.io/library/debian@sha256:d405c1e1d9eecbf30022d23766a0eea235e7f499aa33e357dfd29271a839f82a` (debian stable-slim, pinned in `src/ginn/trust/data/trust.toml`).

Follows T4.9 section 4.3, where `podman create --passwd=false` is refused and the `useradd` step clashes with the entry keep-id writes. The decision (option c of the orchestrator, 2026-10-13) is recorded in the ADR-006 amendment of 2026-10-13 (T4.9b): the realm user is the keep-id entry, sent with `--passwd-entry`, and the `useradd` step is dropped.

- Every probe ran in its own base under `/tmp` (`ginn-t49b-*`), with `--root`, `--runroot`, `--tmpdir` and `--runtime crun`, and its own `XDG_RUNTIME_DIR` (mode 0700). `HOME` and the XDG directories were inside the base too. ## 2. Measurements on podman 5.8.8

| Question | Result |
|---|---|
| `podman create --help`, passwd flags | `--passwd-entry string` (entry written to /etc/passwd), `--group-entry string` (entry written to /etc/group), `--hostuser strings`. |
| `--passwd` | Present on `podman run` only (default true). |
| `create --passwd=false` | Exit 125, `Error: unknown flag: --passwd`. |
| Keep-id, no entry flag (control) | Passwd `soubarna:*:1000:1000:Soubarna:/:/bin/sh`. Group `soubarna:x:1000:soubarna`. Exec `HOME=/`. |
| `--passwd-entry` literal | Written verbatim: `soubarna:*:1000:1000:soubarna:/home/soubarna:/bin/bash`. Exec `HOME=/home/soubarna` with no `HOME` in the create environment. |
| Placeholders in the entry | `$USERNAME` gives the host login name, `$UID` and `$GID` the host ids, `$NAME` the host GECOS (`Soubarna`), and `$HOME` gives `/` when the create environment has no `HOME`. |
| `$` in a path | `/home/a$USERNAMEb` became `/home/asoubarnab`. Nothing escapes `$`, so ginn refuses it. |
| `--group-entry` literal | Written as given. It equals the default group entry for this user and gid. |
| `HOME` in create environment with no entry | The entry stays `:/:/bin/sh`, but exec `HOME` is `/home/soubarna`, so the create environment wins over the entry home. |
| Entry uid differs from the run uid (4242 vs 1000) | The entry is written as given. `getent passwd 1000` exits 2, and exec `HOME` is empty. This is the mismatch the check must catch. |
| `--passwd-entry` without keep-id | Accepted, and the entry is written for uid 1000. ginn refuses it anyway, so the product never relies on it. |
| Image tools | `/usr/bin/getent` and `/bin/bash` are present. `/bin/sh` is dash. |
| `/etc/skel` and `useradd -m -d <existing dir>` | `/etc/skel` has `.bash_logout`, `.bashrc` and `.profile`. `useradd` on an existing directory prints `Not copying any file from skel directory into it.` The Realm Home is an existing directory, so the old step copied nothing. |
| Plain `useradd` (no `-K`) | Writes `probe:100000:65536` to `/etc/subuid`, and one line to `/etc/subgid`. This is what the `-K` flags guarded. With no `useradd`, no line is written (gate, below). |

## 3. Decision

1. The realm user is the keep-id entry: `--passwd-entry <user>:*:<uid>:<gid>:<user>:<host home>:<login shell>`. The login shell is `shell` in `src/ginn/distros/data/*.toml`, the same field `enter` reads (`runtime/enter.py`). All four shipped TOML files already have it (`/bin/bash`), so no data file changed.
2. `CreateSpec.passwd` is replaced by `passwd_entry`. The adapter never emits `--passwd=false`, and refuses an entry without keep-id, an entry that is not seven colon fields, and an entry with `$` or a newline.
3. `ops/create.py` runs no `useradd`. After start and attach it runs `getent passwd <uid>` as container root, in the journal step `user` (name unchanged). The output must equal the entry sent. Exit 2, exit 127 and any other entry fail the create with the new code GINN-E-REALM-USER (exit 1), and the rollback removes the realm.
4. A host home or user name that the entry cannot carry is refused before any podman call, with GINN-E-REALM-USER.
5. HOME: the entry's home is honoured at exec (section 2). `CreateSpec` still sends no `--env`, as before.

## 7. Open

- Arch and Fedora: not run. `getent` and the login shell (`/bin/bash` in `arch.toml` and `fedora.toml`) are unverified there. The check fails closed if `getent` is missing (exit 127 gives GINN-E-REALM-USER).
- Group entry: ginn does not pass `--group-entry`. The default group entry matched the host name and gid in the measured case (primary group named after the user). A host whose primary group has another name was not measured. ginn does not check the group entry.
- A host home containing `$`, `:` or a newline is refused. No escape was measured, and none is attempted. The user moves the home.
- Only debian was run. NFR-007, NFR-005 and NFR-004 numbers are not re-measured here.
- Image already holds the host uid (not measured): when the image has a user with the host uid, keep-id may write no entry, and `getent passwd <uid>` returns the image's line on every create. Debian has no uid 1000 (measured here). Arch and Fedora are not measured here. The check then fails with GINN-E-REALM-USER, and the remedy says to use another distro or report a bug.
- `docs/roadmap.md` T6.7 and ADR-006 "Development" wording now follow this amendment. The rebuild (T8.3) sends the same entry, not a replay of `useradd`.

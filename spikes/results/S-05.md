## S-05r: rerun with catatonit pause

Supersedes the S-05 verdicts. Earlier S-05 numbers ran on runc with podman's own pause. This rerun runs on crun with catatonit as the pause process.

### Framing correction

S-05 said "ginn cannot mitigate the pause, so NFR-002 as written fails for every realm on this host." That was wrong. ginn pins its own runtime dir (`XDG_RUNTIME_DIR`), so podman starts a rootless pause under that dir. The pause is ginn's own process, separate from the user's shared pause. Its cost is small with catatonit (0.68 MiB median). The ginn package ships catatonit, so podman's fixed lookup path (`/usr/libexec/podman/catatonit`) resolves on the host.

### Services-on: blocked (NFR-003 not measured)

- No services-on row exists for `base` or `abd`. There is no NFR-003 verdict and no mitigation figure from S-05r.
- Cause: services-on realms run with `--cgroup-parent /ginn/<uid>/s05r-<cfg>`. crun writes the container's pid into that cgroup's `cgroup.procs`. The sweep shell sits in the session cgroup `0::/2`, and moving a pid needs write access to the common ancestor's `cgroup.procs`. Here that is the root cgroup, owned by root (0644). A direct test (`echo $$ > /sys/fs/cgroup/ginn/1000/s05r-launch/cgroup.procs`) gave `Permission denied`.
- The trial confirmed it. `on-trial base` failed with `Error: crun: write to /sys/fs/cgroup/ginn/1000/s05r-trial-base/libpod-<id>/cgroup.procs: Permission denied: OCI permission denied`. The container never started, so the settle poll never ran.
- Not done: the S-01 root step `--root-move`, which needs sudo. This rerun does not use sudo.
- Unblock: one root step, `sudo spikes/s01_systemd_rootless.sh --root-move 1000 <pid of the sweep shell> <dir>`, then `spikes/s05_idle_rss.sh on base` and `on abd` (both resume-safe). `spikes/s05/settle.sh` has not yet polled a running systemd; the first services-on run should check it.

### Caveats and event record

- Memory event. The first services-off sweep ran on a host short of memory. A background-process reaper stopped the sweep during run 7, after run 6 had finished (run 6 totals 4808 KiB, in range). The sweep resumed under the same sweep id with memory logging (`spikes/s05/mem.tsv`, from run 7 on; runs 1-6 have no memory sample).
- Rows 9 and 10 (first pass) are excluded. Their pause RSS fell to 12 KiB with 36 KiB swapped out (pause 700 KiB before), and realm RSS dropped (1904 and 3728 KiB against 3.8-4.1 MiB elsewhere). The pause's pages appear to have been reclaimed under pressure and not faulted back while the process sat idle (inference from RSS and VmSwap, not traced), so that reading is not steady state. Those rows are kept with status `excluded-pressure` and do not count. The pause was then restarted and both runs were measured again under the same sweep id.
- Rows 7 and 8 were taken in the pressure window. Their pause RSS is 652 KiB (48 KiB below run 1-6), but realm and total are inside the run 2-6 range, so they count. Flagged.
- Run 1 is the lowest counted row (realm 2.75 MiB, total 3.43 MiB). It is the first run after prepare and predates the event. Its memory is not logged. It stays in and sets the min. Dropping it moves the total median from 4.55 to 4.57 MiB.
- The pause pid changed once: rows 1-8 used 9758 and the reruns used 28864. Both were catatonit with the spike environ, checked before each use. `summary` lists both pids.
- Runtime and pause changed together against S-05 (runc with podman pause, to crun with catatonit). The total median fell from 10.58 to 4.55 MiB. Most of the drop is the pause (6.33 to 0.68 MiB). The realm-only median fell from 4.25 to 3.87 MiB, which includes the runtime change. The two effects are not separated.
- Swap: median 0.00 MiB, max 0.03 MiB (rows 7-10).
- `nfr001` tags processes by environ. A container's init (`podman-init`) inherits the container's environ, so the tag misses it. Teardown relied on `rm -f` and `unshare rm`, and the post-teardown checks confirmed no spike paths or processes remain.
- The host had other users' processes running (the user's own pause 30277 and containers). They were not touched.
- xdg-dbus-proxy (FR-068) was not re-measured. The S-05 figure stands as history.

## Method

- Sample: 60 s after the realm starts, RSS from `VmRSS` in `/proc/PID/status`, PSS from `smaps_rollup`. N = 10 runs per config, one realm at a time, median/min/max.
- Realm processes: conmon, every descendant of conmon (the container PID 1 is conmon's child; conmon is a subreaper), plus members of the realm's libpod cgroup scope when the init sits in one. Services-off has no cgroup of its own (it runs in the session scope `0::/2`), so the descendant walk is the only method used there.
- Pause: the rootless `podman pause` process (`comm` "podman pause"), found with a read-only `ps` scan. It is shared by every storage root of the user, so it is reported apart from the realm. In every sweep run it was pid 30277, which started 12:04:17 and was not started by S-05.
- Window: services-off starts the 60 s window at container start. Services-on starts it when the in-sweep exec returns, about 0.1 s after start; see Caveats for why, and the separate settle check.
- Host state during the run: MemAvailable 1.5 to 4.4 GB, about 10 GB of swap in use by other work. Other spikes ran concurrently on separate storage roots.

## Mitigations (exact content under `spikes/s05/`)

- (a) `spikes/s05/journald-volatile.conf`, installed as `/etc/systemd/journald.conf.d/50-ginn-s05-volatile.conf`:
  ```
  [Journal]
  Storage=volatile
  RuntimeMaxUse=8M
  ```
  Tradeoff: journals are in RAM and lost when the realm stops.
- (b) `spikes/s05/masks-base.txt`: each unit is masked by a symlink to `/dev/null` under `/etc/systemd/system`. Units: `systemd-udevd.service`, `systemd-udevd-control.socket`, `systemd-udevd-kernel.socket` (added so socket activation cannot start the masked udevd), `systemd-udev-trigger.service`, `getty@tty1.service`, `console-getty.service`, `apt-daily.timer`, `apt-daily-upgrade.timer`, `e2scrub_all.timer`, `fstrim.timer`. In this image udevd, udev-trigger, getty@tty1 and e2scrub_all have no unit file, so their masks do nothing. The measured effect of (b) is -0.2 MiB, inside noise.
- (b, logind) `spikes/s05/masks-logind.txt`: `systemd-logind.service` masked as well. Untested for FR-080 apps; this needs the FR-080 test before adoption.
- (c) `--no-install-recommends`: already in the S-01 image, so it is the baseline. Its comparison (`norec`, build in `spikes/s05/Dockerfile.recommends`) costs +0.4 MiB. It is not a saving on top of the baseline.
- (d) `SYSTEMD_LOG_LEVEL=warning`, set as a run-time environment variable. PID 1 honours it: the journal shrinks from 54 lines to 7 (checked in a settle run). RSS effect is nil (40.55 vs 40.59 MiB).
- Image layers: `spikes/s05/Dockerfile.mit` with build args `JOURNAL` and `MASKS` (`none`, `base`, `logind`) on top of the S-01 base image.

## Recommendations for ADR-007 (superseded by the S-05r recommendations above)

Items 2 and 3 assume the pause is per user and cannot be mitigated. S-05r corrects that. Kept as history.

1. Resident helpers in a services-off realm: conmon (about 1.9 MiB) and the init (catatonit, about 0.7 MiB). Any other keep-alive process counts against the 8 MiB budget. The `sleep` placeholder (1.7 MiB) is a measurement stand-in, not a required helper.
2. The rootless `podman pause` is per user and shared. It costs 3.6 to 6.5 MiB RSS (mostly file-backed podman binary pages) and 0.2 to 2 MiB PSS, and it is not per realm. ADR-007 must state how it is counted. Options: (a) exclude it from the realm budget as per-user runtime overhead and amend NFR-002 to say so; (b) keep NFR-002 as written, which fails. This decision belongs to the SRS owner.
3. xdg-dbus-proxy must be lazy (FR-068). One proxy is about 4.7 MiB RSS, which alone pushes a services-off realm past 8 MiB (realm-only 9.0 MiB).
4. Services-on defaults for NFR-003: journald volatile, 8 MiB cap, `SYSTEMD_LOG_LEVEL=warning`, and the base mask list. That is a+b+d at 37.8 MiB (2.2 MiB headroom). Mask logind (abld, 29.6 MiB) only after an FR-080 test shows the apps do not need it.
5. Gate on the median, not the mean, and report pause and proxy as separate columns in every measurement.

## Caveats and deviations

- **State column (script defect, not fixed in the committed run).** The in-sweep exec returned before systemd's bus was up, so the `state` column shows `0`, `none` or `initializing` in most rows, and `is-system-running --wait` returned at once. The 60 s samples are still valid: the realm had settled (nproc 4 and normal RSS, and the settle check above). Repair the exec for future runs: poll the state inside the container before the window starts.
- **Pause RSS varies (3.6 to 6.5 MiB).** Its RSS is mostly file-backed; it drops when the host reclaims page cache under memory pressure (MemAvailable was about 1.5 GB during the final sweep). PSS shifts with how many processes share those pages. Read the pause row as a range, not a constant.
- **Swap.** Each realm had 0.2 to 0.7 MiB of VmSwap, so RSS understates slightly. Adding it moves the medians by about +0.5 MiB: base to 41.1 (still FAIL), abd to 38.3 (still PASS).
- **Settle check** covers one run per config. The 10-run statistics come from the sweep.

## S-05b: catatonit as rootless pause (superseded by S-05r)

Superseded by S-05r. On this host the fixed path now resolves to catatonit 0.1.7 (`/usr/libexec/podman/catatonit`, a link to `/usr/libexec/catatonit/catatonit`), and S-05r measured the catatonit pause on crun. The "NOT MEASURED" verdict and the root-step recommendation below are history.

Run: 2026-10-12, host Void glibc x86_64, kernel 7.2.9_1, podman 5.8.8 (Void build, `podman version` reports no git commit), crun 1.30.1, conmon 2.2.1.
Script: `spikes/s05b_catatonit_pause.sh` (`prepare`, `probe`, `knobs`, `teardown`). It refuses to run unless `XDG_RUNTIME_DIR=/run/user/1000/ginn-spike-s05b-xrd`, and pins that value on every podman call. Scratch bin, conf and logs stayed outside the repo.

### Verdict

**S-05b: NOT MEASURED.** Podman 5.8.8 runs `catatonit -P` as its rootless pause, but only from two fixed paths. This host has neither path, and the brief forbids placing one. The catatonit configuration therefore did not run, and no catatonit NFR figures exist.

- Podman uses catatonit when `/usr/libexec/podman/catatonit` or `/usr/bin/catatonit` exists. Otherwise it falls back to its own pause, `comm` "podman pause". Source below.
- `helper_binaries_dir` and `init_path` do not change the rootless pause. Both were tried, and the pause stayed podman's own.
- On this host `/usr/libexec/podman` exists (root-owned) and holds no `catatonit`. `/usr/bin/catatonit` is absent.
- The S-05 figures stand: services-off pause RSS median 6.33 MiB, realm-only 4.25 MiB. NFR-002 (<= 8 MiB) and NFR-003 (<= 40 MiB) verdicts are unchanged from S-05.

Next step, which needs one root step by the owner: place the static catatonit (sha256 below) at `/usr/libexec/podman/catatonit`, rerun `probe` under the same pin, then rerun the S-05 services-off and services-on baseline rows with catatonit as the pause (same method: 10 runs, 60 s window, median, pause attributed by its own pid file).

### Catatonit binary

- Debian `catatonit` 0.2.1-2+b14, from `docker.io/library/debian:stable` (image id `fe0233b1a375...`, digest `sha256:d95c640a...`), copied out of a throwaway container in spike storage, as S-05 did. Nothing installed on the host, no xbps.
- `file`: statically linked. `ldd`: not a dynamic executable. Runs on Void: `tini version 0.2.1_catatonit`.
- sha256 `32ab6262b8735f567bfc42515218905e40dc8306aa2d763ffbffeb3956a20a96`.

### How podman picks the pause

- Source, read for this spike: `containers/podman` v5.8.8, `pkg/rootless/rootless_linux.c`, `do_pause()`. Podman is Apache-2.0 (the tag's LICENSE file). The brief's man-page rule covers unknown licences only. Lines, verbatim:
  ```c
  /* Attempt to execv catatonit to keep the pause process alive.  */
  execl (LIBEXECPODMAN "/catatonit", "catatonit", "-P", NULL);
  execl ("/usr/bin/catatonit", "catatonit", "-P", NULL);
  /* and if the catatonit executable could not be found, fallback here... */

  prctl (PR_SET_NAME, "podman pause", NULL, NULL, NULL);
  while (1)
    pause ();
  ```
  `LIBEXECPODMAN` is compiled in (`${PREFIX}/libexec/podman` in the Makefile). The installed binary contains the literal strings `/usr/libexec/podman/catatonit` and `/usr/bin/catatonit`. No config key changes these paths.
- The rootless pause is podman re-executed with `_PODMAN_PAUSE=1`. Observed: `/proc/PID/exe` is `/usr/bin/podman`, `comm` is `podman pause`.
- Man pages (containers.conf(5), podman(1)): no key selects the rootless pause. `helper_binaries_dir` lists catatonit for `--init`. `init_path` is for `--init`. `infra_command` and `infra_image` configure pod infra containers.
- Pause pid file: `$XDG_RUNTIME_DIR/libpod/tmp/pause.pid` (source line 536, suffix `/libpod/tmp/pause.pid`). `--tmpdir` does not move it. Evidence below.

### Calls that ran without the pin (safety record)

Four groups of podman calls ran before the pin (about seven invocations). They had no `XDG_RUNTIME_DIR` set to the spike dir, so podman used the default `/run/user/1000`:

1. `pull -q docker.io/library/debian:stable` and the catatonit `run --rm` extraction, during setup (about 14:10). Spike root, runroot and tmpdir were passed.
2. `version` and `info --format ...`, the first probe (spike root, runroot and tmpdir were passed).
3. `run --rm docker.io/library/debian:stable true`, the second probe (spike root, runroot and tmpdir were passed).
4. `podman version --format ...` and `podman info --format ...` after the verdict, with no `--root`, `--runroot`, `--tmpdir` or `CONTAINERS_CONF`. This used the user's default storage. It breaks AGENTS.md.

What the unpinned calls saw:
- After calls 2 and 3, the process list showed only the user's pause, pid 30277. No new pause process appeared.
- After call 4, the list showed the user's pause (30277) and the user's `podman run` (pid 28208, another project).
- Pid 30277's environ at check time: `XDG_RUNTIME_DIR=/run/user/1000`. It is the user's, and nothing signalled it. Podman read its `pause.pid`. No new pause appeared, so it joined this one (inferred).
- `/run/user/1000/libpod` and `/run/user/1000/libpod/tmp` mtimes stayed at 12:04:17. `/run/user/1000/crun` and `/run/user/1000/netns` were last modified at 14:11:23. That time cannot be tied to my calls. The user's concurrent run was active. Entries newer than 14:05 are not present in either dir. Their contents were not inspected further.

### Pause.pid isolation

- Default `XDG_RUNTIME_DIR` (`/run/user/1000`) with `--tmpdir` in spike storage: podman joined the user's existing pause (pid 30277) and created none of its own.
- `XDG_RUNTIME_DIR` set to a spike dir, `--tmpdir` at `<runroot>/libpod-tmp`: failed with `open .../libpod/tmp/pause.pid: no such file or directory`.
- `XDG_RUNTIME_DIR` set to a spike dir, `--tmpdir` at `<xdg>/libpod/tmp`: podman created its own pause and wrote `pause.pid` there.
- Consequence: any spike that does not pin `XDG_RUNTIME_DIR` joins the user's shared pause.

### Knobs tried

- `helper_binaries_dir` with the scratch bin first (config A).
- `[engine] init_path` set to catatonit (config B).

- Read upstream `pkg/rootless/rootless_linux.c` for the pause lookup. This decided the verdict.
- Not tried: a catatonit at a fixed path (needs root), `podman system migrate` (state-changing, not in brief).

- Four unpinned podman calls, listed above. Call 4 used the default storage and breaks AGENTS.md's rule on `--root`, `--runroot` and `--tmpdir`.
- `XDG_RUNTIME_DIR` is now `/run/user/1000/ginn-spike-s05b-xrd`, as the coordinator requires. Runroot stays at `/run/user/1000/ginn-spike-s05b`.
- No 60 s services-off or services-on sweep ran. The catatonit path needs root.

### Recommendation

- ADR-007: the catatonit pause applies only on hosts where `/usr/libexec/podman/catatonit` or `/usr/bin/catatonit` exists. Treat it as a host package dependency. Keep the S-05 pause counting (option a) until a catatonit run exists.
- Pin rule: any spike that runs podman must set `XDG_RUNTIME_DIR` to its own directory and refuse otherwise. AGENTS.md's hard runtime rules should carry this rule, since `--tmpdir` alone does not isolate the pause.

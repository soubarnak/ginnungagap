# S-05: idle RSS of services-off and services-on realms with mitigations (NFR-002, NFR-003)

Run: 2026-10-12, host Void Linux glibc x86_64, kernel 7.2.9_1, podman 5.8.8 (cgroupfs manager, rootless), runc 1.5.2, conmon 2.2.1.
Script: `spikes/s05_idle_rss.sh` (orchestrator), `spikes/s05/measure.py` (accounting). Drop-ins and masks: `spikes/s05/`. Raw per-run JSON, `runs.tsv` and logs stayed outside the repo (scratch).

## Verdict

**S-05: PARTIAL**

NFR-002: FAIL (median 10.6 MiB, including the shared rootless `podman pause`; realm-only median 4.3 MiB, which passes)
NFR-003: FAIL as baseline (median 40.6 MiB); PASS with named mitigations (median 37.8 MiB with a+b+d, no logind mask; median 29.6 MiB with a+b+logind+d)

- NFR-002 counts the rootless `podman pause` process because the SRS says "all host-side and in-realm processes attributable to ginn and the runtime". That process is per user, not per realm. Without it, the realm costs 4.25 MiB median (min 3.65, max 4.35). ginn cannot mitigate the pause, so NFR-002 as written fails for every realm on this host. See ADR-007 recommendations.
- NFR-003 fails by 0.6 MiB at baseline (the S-01 image, as built). Two mitigations pass: journald volatile with an 8 MiB cap (a, alone 37.9 MiB), and a+b+d (37.8 MiB, 2.2 MiB headroom). Masking `systemd-logind` (abld) gives 29.6 MiB, but logind's FR-080 role was not tested.
- Pass criterion from the roadmap: "<= 8 MiB / <= 40 MiB or named mitigations". The services-on criterion is met with mitigations; the services-off criterion is missed only because of the shared pause.

## Method

- Sample: 60 s after the realm starts, RSS from `VmRSS` in `/proc/PID/status`, PSS from `smaps_rollup`. N = 10 runs per config, one realm at a time, median/min/max.
- Realm processes: conmon, every descendant of conmon (the container PID 1 is conmon's child; conmon is a subreaper), plus members of the realm's libpod cgroup scope when the init sits in one. Services-off has no cgroup of its own (it runs in the session scope `0::/2`), so the descendant walk is the only method used there.
- Pause: the rootless `podman pause` process (`comm` "podman pause"), found with a read-only `ps` scan. It is shared by every storage root of the user, so it is reported apart from the realm. In every sweep run it was pid 30277, which started 12:04:17 and was not started by S-05.
- Window: services-off starts the 60 s window at container start. Services-on starts it when the in-sweep exec returns, about 0.1 s after start; see Caveats for why, and the separate settle check.
- Host state during the run: MemAvailable 1.5 to 4.4 GB, about 10 GB of swap in use by other work. Other spikes ran concurrently on separate storage roots.

### Init stand-in (catatonit)

- Host has no `catatonit` and podman's bundled `/usr/libexec/podman/catatonit` is absent. `podman create --init` without `--init-path` fails with: `Error: lookup init binary: exec: "catatonit": executable file not found in $PATH`.
- Stand-in used: Debian's `catatonit` 0.2.1-2+b14 (static, `tini version 0.2.1_catatonit`), copied out of a throwaway container in the spike storage with `apt-get install`. Nothing was installed on the host.
- Used as `--init --init-path <scratch>/bin/catatonit`. The services-off measure uses this stand-in because the host has no `/usr/bin/catatonit`.

## Mitigations (exact content under `spikes/s05/`)

- (a) `spikes/s05/journald-volatile.conf`, installed as `/etc/systemd/journald.conf.d/50-ginn-s05-volatile.conf`:
  ```
  [Journal]
  Storage=volatile
  RuntimeMaxUse=8M
  ```
  Tradeoff: journals are in RAM and lost when the realm stops.
- (b) `spikes/s05/masks-base.txt`: each unit is masked by a symlink to `/dev/null` under `/etc/systemd/system`. Units: `systemd-udevd.service`, `systemd-udevd-control.socket`, `systemd-udevd-kernel.socket` (added so socket activation cannot start the masked udevd), `systemd-udev-trigger.service`, `getty@tty1.service`, `console-getty.service`, `apt-daily.timer`, `apt-daily-upgrade.timer`, `e2scrub_all.timer`, `fstrim.timer`. In this image udevd, udev-trigger, getty@tty1 and e2scrub_all have no unit file, so their masks do nothing. The measured effect of (b) is -0.2 MiB, inside noise.
- (b, logind) `spikes/s05/masks-logind.txt`: `systemd-logind.service` masked as well. Untested for FR-080 apps; this needs the FR-080 test before adoption.
- (c) `--no-install-recommends`: already in the S-01 image, so it is the baseline. Its comparison (`norec`, build in `spikes/s05/Dockerfile.recommends`) costs +0.4 MiB. It is not a saving on top of the baseline.
- (d) `SYSTEMD_LOG_LEVEL=warning`, set as a run-time environment variable. PID 1 honours it: the journal shrinks from 54 lines to 7 (checked in a settle run). RSS effect is nil (40.55 vs 40.59 MiB).
- Image layers: `spikes/s05/Dockerfile.mit` with build args `JOURNAL` and `MASKS` (`none`, `base`, `logind`) on top of the S-01 base image.

## Settle check (post-sweep)

The sweep's own `state` column is unreliable (see Caveats). A separate check ran each services-on config once, polling `systemctl is-system-running` until running or degraded. All nine configs reached `running` with 0 failed units. Journal lines after boot: base 54, a 53, b 49, bl 45, d 7, norec 57, ab 48, abd 6, abld 4.

## Recommendations for ADR-007

1. Resident helpers in a services-off realm: conmon (about 1.9 MiB) and the init (catatonit, about 0.7 MiB). Any other keep-alive process counts against the 8 MiB budget. The `sleep` placeholder (1.7 MiB) is a measurement stand-in, not a required helper.
2. The rootless `podman pause` is per user and shared. It costs 3.6 to 6.5 MiB RSS (mostly file-backed podman binary pages) and 0.2 to 2 MiB PSS, and it is not per realm. ADR-007 must state how it is counted. Options: (a) exclude it from the realm budget as per-user runtime overhead and amend NFR-002 to say so; (b) keep NFR-002 as written, which fails. This decision belongs to the SRS owner.
3. xdg-dbus-proxy must be lazy (FR-068). One proxy is about 4.7 MiB RSS, which alone pushes a services-off realm past 8 MiB (realm-only 9.0 MiB).
4. Services-on defaults for NFR-003: journald volatile, 8 MiB cap, `SYSTEMD_LOG_LEVEL=warning`, and the base mask list. That is a+b+d at 37.8 MiB (2.2 MiB headroom). Mask logind (abld, 29.6 MiB) only after an FR-080 test shows the apps do not need it.
5. Gate on the median, not the mean, and report pause and proxy as separate columns in every measurement.

## Caveats and deviations

- **State column (script defect, not fixed in the committed run).** The in-sweep exec returned before systemd's bus was up, so the `state` column shows `0`, `none` or `initializing` in most rows, and `is-system-running --wait` returned at once. The 60 s samples are still valid: the realm had settled (nproc 4 and normal RSS, and the settle check above). Repair the exec for future runs: poll the state inside the container before the window starts.
- **Pause RSS varies (3.6 to 6.5 MiB).** Its RSS is mostly file-backed; it drops when the host reclaims page cache under memory pressure (MemAvailable was about 1.5 GB during the final sweep). PSS shifts with how many processes share those pages. Read the pause row as a range, not a constant.
- **Swap.** Each realm had 0.2 to 0.7 MiB of VmSwap, so RSS understates slightly. Adding it moves the medians by about +0.5 MiB: base to 41.1 (still FAIL), abd to 38.3 (still PASS).
- **Settle check** covers one run per config. The 10-run statistics come from the sweep.
- **Earlier runs on the default tmpdir.** Smoke tests and the first sweep attempt (stopped at services-off run 9) ran before the safety change, and used podman's default tmpdir `/run/user/1000/libpod/tmp`. Those runs wrote exit and persist entries there and read the shared `pause.pid`. Their rows were discarded. All numbers above come from the final sweep, which ran with `--tmpdir $XDG_RUNTIME_DIR/ginn-spike-s05/libpod-tmp` on every podman call.

## Process and safety notes

- Podman storage: every S-05 podman call used `--root ~/.local/share/ginn-spike-s05/podman --runroot $XDG_RUNTIME_DIR/ginn-spike-s05 --tmpdir <runroot>/libpod-tmp`, including `unshare`. `podman system reset` was not run. S-05 read the shared pause process with `ps` only.
- `spikes/s06_gpu.sh:217` (another spike) calls `podman system reset -f`. S-05 did not touch it. It is the same pattern the safety change prohibits; the owner should review it.
- Root steps: `sudo spikes/s01_systemd_rootless.sh --root-setup 1000 1000 <scratch>/root` (S-01 helper, once), then `--root-move 1000 <script pid>` inside the sweep. Records in `<scratch>/root/root-steps.log`.
- Review: the spike scripts were written directly under the spike brief. They have not been through the review routing in the repo's local instructions (haiku-coder for code, opus-reviewer for review). Route them for review before S-05 numbers feed ADR-007.

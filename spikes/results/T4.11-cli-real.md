Run: 2026-10-13, kernel 7.2.9_1 (Void, glibc). The podman and crun versions of this host are the ones recorded in `spikes/results/T4.9b-realm-user.md` (podman 5.8.8 rootless, crun 1.30.1). They were not queried again, because the rules forbid a bare `podman` call.

Command, with the gate's result file set: `GINN_INTEGRATION=1 GINN_T49_RESULTS=<file> pytest -q -s tests/integration/test_cli_real.py`. Result: `1 passed in 19.65 s`. This is the final run, on the code in the working tree. Two earlier runs of the same test also passed; the earlier 100-run p95 was 0.128 s and the earlier create 5.454 s. The test is `test_cli_smoke_one_realm_end_to_end` in `tests/integration/test_cli_real.py`.

## 1. What the smoke runs

- Realm `clismoke`, distribution `debian`. The image is the digest pinned in `src/ginn/trust/data/trust.toml`: `sha256:d405c1e1d9eecbf30022d23766a0eea235e7f499aa33e357dfd29271a839f82a`.
- Every command goes through `ginn.__main__.main`, which builds the production objects in `ginn/cli/_context.py`. Only the host seams are replaced, as the T4.9 gate does: `Seams.integrate` is False, so the create runs no refresh and no package step (Gate 3 is not approved), and the mount roots of the user are hidden.
- Storage is an isolated base under `/tmp` (`ginn-it-*`), with its own `XDG_*`, `GINN_RUNTIME_DIR` and `XDG_RUNTIME_DIR`. Teardown removed it. The store's pause process was gone afterwards (`alive_after_kill: false`), and no `/tmp/ginn-it-*` directory was left.
- Nothing touched `~/.local/share/containers` or `/run/user/<uid>/libpod`.

Each step asserts its result. Checked on the host: status JSON reports `state` running, `container_state` running and `state_mismatch` false; `exec --root` prints `ok`; `exec ... sh -c 'exit 7'` returns 7; `list --json` shows the realm stopped after the stop; `delete` reports `Realm Home kept`; `status` after the delete returns 3 (GINN-E-NO-SUCH-REALM).

The 100-run series is in process: it includes argument parsing, the recovery scan, the realm look, the re-attach pre-check and the podman exec. It excludes Python interpreter start-up. NFR-004 is p95 at most 300 ms on the enter path, measured by the T4.9 gate. The subprocess (`python -m ginn exec`) p95 is not measured here. It belongs to T10.4 (`tools/measure/*.sh` for NFR-001..011).

## 3. What this record proves, and what it does not

- Proves: FR-049 AC-1 on the host through the CLI (`sh -c 'exit 7'` returns 7 in a debian realm). FR-042 `exec --root` runs inside the realm. FR-048 `enter` without a terminal exits 0. FR-016, FR-020 and FR-010 (a stopped debian realm is created, with package steps off).
- Does not prove: FR-006 warnings on a host (unit tests only, T4.11). The confirmed purge of a real Realm Home through the CLI (unit tests only). The FR-025 second-user run (T10.5). The package installed-list (AC-1, AC-2 of FR-010, T4.9 gate). The subprocess-level NFR-004 (T10.4).
